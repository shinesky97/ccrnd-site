# 인간 검토·승인 정책 (Human Review Policy) — 정본

- 버전: 1.0 · 기준일: 2026-07-30
- 이 문서는 "자동화 가능한 절차"와 "회계사 승인이 필요한 판단"의 구분에 대한 **단일 정본**이다.
- 코드 구현: 각 산출물의 `requires_professional_judgment`, `reviewer_approval_required` 필드와
  workflow 모듈의 승인 게이트. 게이트 미통과 판단은 후속 단계에서 참조 불가.

## 1. 완전 자동화 (시스템/AI 수행, 회계사 검토는 사후적)

**결정적 계산·검증·대사** — 파일 검증·해시, 차대 검증, TB↔GL↔FS 대사, 증감·비율·추이 분석,
단위 혼재·중복·음수 탐지, 규칙 기반 이상분개 플래그, 모집단 완전성 검증, seed 기반 표본 "추출 실행",
중요성 "계산안" 산출, 중요계정 후보 목록화, 감사차이 합산·비율 계산, 요약표·서식·상태·이력 관리.

**AI 보조 생성 (반드시 '제안' 상태로 저장)** — 사업모델·계약·의사록 요약, 변동사항 서술 초안,
위험 후보, 감사프로그램 초안, 추가절차 제안, 조서 서술부 초안, 보고서 문단 초안, 불일치 플래그.

## 3. 자동화 금지 (시스템이 시도하지 않는 것)

- 감사의견의 자동 결정·기본값 설정 (의견 필드에 기본값 없음, AI 쓰기 경로 부재)
- 조회서 회신의 진위 판단
- 존재하지 않는 증거·거래·금액의 생성
- 승인 단계 우회, 권한 자동 상승
- 원본 파일의 수정·삭제

## 4. 자동 검토대상 분류 규칙

다음 중 하나면 산출물은 자동으로 NEEDS_REVIEW로 분류된다.

- AI 출력의 `confidence = low`
- `evidence_refs`가 비어 있음
- JSON Schema 검증 실패 (이 경우 저장 자체가 거부되고 재처리 큐로)
- 결론 필드는 있으나 근거 링크가 없는 조서 (완료 전이 하드 블록)
- 이상항목 금액 ≥ 수행중요성

## 5. 승인 기록 요건

- 모든 승인·반려는 `approvals`에 행위자·시각·결정·**사유**와 함께 기록.
- 일괄 승인(bulk approve) UI는 제공하지 않는다 (자동화 편향 방지).
- 승인 화면에는 AI 제안 라벨, confidence, 원천 근거를 병렬 표시한다.
