# 제품 요구사항 정본 (Product Requirements)

- 버전: 1.0 · 기준일: 2026-07-30
- 원 요구사항: 발주자 명세(2026-07-29) + 확정 결정사항(2026-07-30, initial-design.md 참조)

## 1. 목적

AI가 독립적으로 감사의견을 확정하거나 감사보고서를 발행하는 것이 **아니다**.
회계사가 승인한 감사계획과 중요성 기준에 따라 일반적인 회계감사 절차를 체계적으로 수행하고,
감사증거와 판단 근거를 정리하여 **감사조서와 감사보고서 초안**을 생성한다.

## 2. 기본 원칙 (요구사항 §1 — 위반 불가)

1. 입력자료에 존재하지 않는 거래·계정·금액·계약·통제·감사증거를 만들지 않는다.
2. 자료 부족 시 추정·단정 금지 → "자료 부족", "추가 확인 필요", "담당자 판단 필요" 표시.
3. 모든 결론에 원천자료·파일명·페이지/시트·셀 범위·추출값·수행절차·판단 근거를 연결한다.
4. 감사결론과 감사의견은 AI가 단독 확정하지 않는다.
5. 중요성·수행중요성·명백히 경미한 왜곡표시 기준은 담당 회계사가 입력하거나 승인한다.
6. 위험평가·표본선정·추정치 평가·계속기업·특수관계자·부정위험·감사의견 결정에는 회계사 승인 단계를 둔다.
7. 원본자료는 수정하지 않고 읽기 전용으로 보존한다.
8. 데이터 변경·판단 변경·검토·승인의 이력을 모두 감사로그에 남긴다.
9. 개인정보·고객정보를 로그에 평문으로 노출하지 않는다. (AI 송신은 확정 결정에 따라 원문 허용 — security-model.md §4의 권고·제약 참조)
10. 최종 감사보고서 생성 전 필수 검토 체크리스트가 모두 통과되어야 한다.

## 3. 확정된 핵심 파라미터

| 항목 | 값 |
|---|---|
| 적용 회계기준 기본값 | 일반기업회계기준(K-GAAP). K-IFRS는 엔진 확장 옵션 |
| 적용 감사기준 | 대한민국 회계감사기준 (ISA 기반) |
| 전체 중요성(OM) 기본 공식 | (자산총액 + 매출총액) ÷ 2 × 1% — 계산안으로 제시, Partner 승인 필수 |
| 수행중요성(PM) 기본 제안 | OM × 75% (범위 50~75%, 조정 가능, 승인 필수) |
| 명백히 경미한 기준 기본 제안 | OM × 5% (이하, 조정 가능, 승인 필수) |
| 표본 수 추천 방식 | 비통계적 보증계수 방식 (audit-methodology.md §7) — 추천안 제시, 승인 필수 |
| 파일 저장소 | Google Drive (원천자료 + 산출물 백업). dev는 로컬 파일시스템 |
| AI 송신 정책 | 원문 송신. 고유식별정보 자동 마스킹 기본 유지 권고 (security-model.md §4) |

## 4. 대상 입력자료 (초기 버전)

회사 기본정보·사업 이해 자료 / 전기 감사보고서·전기 감사조서 / 당기·전기 재무제표 / 시산표 /
총계정원장 / 분개장 / 계정별 원장 / 매출·매입 명세 / 거래처별 채권·채무 명세 / 은행계좌·차입금 명세 /
유형자산 명세 / 재고자산 명세 / 급여·퇴직급여 자료 / 법인세·세무조정 자료 / 주주명부·의사록 /
주요 계약서 / 외부조회 자료(금융기관·채권채무 등) / 후속사건 자료 / 경영진확인서 / 연결·주석 작성자료

**지원 형식**: XLSX, CSV, PDF, DOCX (HWP는 PDF/DOCX 변환본 수용). 스캔 PDF의 OCR은 초기 미지원 —
"OCR 필요" 플래그만 기록.

## 5. 감사 워크플로우 모듈 (각각 독립 모듈)

A. 업무 수임 및 독립성 (최종 수임 결정: 회계사만)
B. 기업과 환경의 이해 (설명 vs 원천자료 불일치 플래그 포함)
C. 중요성 설정 (계산안 제시, 기준·비율 임의 확정 금지)
D. 위험평가 (재무제표 수준 / 주장 수준 분리, 8개 주장, 유의적·부정위험은 회계사 승인)
E. 분석적 절차 (14종 분석 — audit-methodology.md §5)
F. 계정과목별 감사 프로그램 (20개 계정 영역, 15개 필드 구조)
G. 표본선정 (모집단 완전성 검증, seed 저장, 재현 가능, 표본 수 승인 필수)
H. 조회 및 증빙검사 (발송·회신 진위 판단은 자동화하지 않음)
I. 감사차이 관리 (수정분개·미수정왜곡표시 요약표 자동 생성)
J. 감사 완료 절차 (체크리스트 전 항목 통과 필수)
K. 감사보고서 초안 (의견은 명시적 선택 + Partner 승인 없이 생성 불가)

상세 절차·필드 정의는 audit-methodology.md, 데이터 구조는 data-model.md 참조.

## 6. AI 출력 규칙

- 자유 서술문만 반환 금지 → 구조화 데이터(schemas/ai_envelope.v1.json) 저장.
- 필수 필드: conclusion, confidence, evidence_refs, source_locations, calculations, assumptions,
  missing_information, exceptions, proposed_follow_up, requires_professional_judgment,
  reviewer_approval_required.
- `confidence=low` 또는 `evidence_refs=[]` → 자동 검토대상 분류.
- JSON Schema 검증 실패 → 저장하지 않고 재처리 또는 사용자 검토 상태 전환.

## 7. 상태관리

NOT_STARTED → IN_PROGRESS → WAITING_FOR_CLIENT → NEEDS_REVIEW → REVIEW_COMMENT →
REWORK_REQUIRED → CLEARED → PARTNER_APPROVAL_REQUIRED → COMPLETED → LOCKED

COMPLETED/LOCKED 자료 변경 시 새 버전 생성 + 변경이력 기록.

## 8. 품질검증 시나리오 (12종 — tests/quality_scenarios/)

정상 시산표 / 차대 불일치 시산표 / 중복 분개 원장 / 결산일 후 매출 / 음수 매출채권 /
거래처명 표기 불일치 / 단위(원·천원·백만원) 혼재 / 재무제표↔시산표 불일치 /
조회서 회신금액 상이 / 미수정왜곡 누계의 중요성 초과 / 계속기업 경고신호 / 감사증거 부족

각 기능에 단위테스트 + 통합테스트 + 사람이 확인 가능한 예상 결과를 작성한다.

## 9. MVP 범위

- **MVP 1**: 업무 등록 → 시산표·원장 업로드·검증 → 대사 → 변동분석 → 중요성 → 중요계정 식별 →
  이상분개 탐지 → 위험 후보 → 감사프로그램 → 조서 초안 → 검토·승인 워크플로우 → 미해결 대시보드
- **MVP 2**: 매출·매출채권 / 현금·금융기관조회 / 유형자산 / 매입채무·차입금 / 표본선정 / 감사차이 관리
- **MVP 3**: 재고 / 충당부채·추정치 / 법인세 / 특수관계자 / 후속사건 / 계속기업 / 주석 체크 / 보고서 초안

구현 순서 상세: initial-design.md §7. 각 MVP 사이에 발주자 검수 게이트를 둔다.
