# 외감 실무 자동화 데스크톱 프로그램 — 설계서

- 버전: 0.1 (발주자 검토용) · 기준일: 2026-08-03
- 근거: 발주자 요구 (2026-08-03 접수 — 초기세팅 자동화 / 다업체 진행현황 관리 / 외감 작업순서)

## 0. 포지셔닝 — 기존 설계와의 관계

기존 initial-design.md의 웹 시스템(FastAPI+Next.js)은 장기 목표로 유지하되,
**즉시 실무에 쓸 수 있는 로컬 데스크톱 프로그램을 먼저 만든다.** 이유:

- 감사자료가 발주자 PC의 OneDrive 폴더(`C:\Users\shine\OneDrive - 회계법인 창천\C 회계감사\...`)에
  있고, 실제 업무가 엑셀 파일 조작(이월 세팅·값복사) 중심이다.
- 파일 업로드 없이 **폴더를 직접 지정**해서 처리해야 한다.
- 이 도구에서 축적되는 실행 기록이 진행현황 관리의 데이터가 된다.

핵심 원칙은 동일하게 적용: **원본 미수정(복사본 생성)**, 모든 실행 기록 로그,
**감사판단(결론·의견)은 프로그램이 결정하지 않고 발주자 입력값만 반영.**

## 1. 제품 형태

| 항목 | 결정안 |
|---|---|
| 실행 환경 | Windows 로컬 프로그램. Python + tkinter GUI → PyInstaller로 단일 exe 배포 |
| 파일 처리 | openpyxl (엑셀 읽기/쓰기), 원본은 절대 수정하지 않고 당기 폴더에 새 파일 생성 |
| 데이터 저장 | 프로그램 DB 없이 파일 기반: 업체 루트에 `_audit_tool/` 폴더(실행로그 JSONL, 상태 JSON) |
| 화면 구성 | 탭 2개 — [① 초기세팅] [② 진행현황] (+ 후속: [③ 조서지원]) |

GUI 최소 구성 (탭 ①):

```

│                                              │
│ 자동 식별된 파일:                              │

│   전기 정산표    : wp_8600A_정산표_2024.xlsx ✔  │
│   전기 일반조서  : wp_일반조서_2024.xlsx     ✔  │
│   전기 계정별조서: wp_4000_계정별_2024.xlsx  ✔  │
│   당기 Raw data : rawdata/ (7개 파일)       ✔  │
│                                              │
│ [결정값 입력/확인]  [미리보기(Dry-run)]  [실행] │

```

## 2. 모듈 ① 초기세팅 자동화 (Rollforward)

### 2.1 입력: 폴더 자동 식별

지정 폴더(및 1단계 하위 폴더)에서 파일을 자동 식별한다. 식별 규칙:

- 파일명 키워드(DSD, 정산표, 일반조서, 계정별/4000) + **내용 검증**(시트 구성:
  정산표=AR/SAD/CF/FN, 일반조서=Index+1100..8600, 계정별=입증감사절차+알파벳 시트)
- 연도 판별: 파일명 연도 + 내부 결산일 셀. 전기/당기 구분이 모호하면 실행을 멈추고 사용자 확인.
- 식별 실패 항목은 GUI에서 사용자가 직접 지정 가능.

### 2.2 사전 결정값 입력 (실행 전 필수 — 발주자가 결정하는 것)

실행 전에 아래 값을 입력·확인받는다. 각 항목에 "이 값이 어디에 쓰이는지"를 표시한다.

| 입력값 | 용도 |
|---|---|
| 회사명 | 모든 산출물 헤더 |
| 당기 결산일 / 감사대상 기간 | 조서·정산표·DSD 표지, 기수 계산 검증 |
| 당기 기수(제N기) / 귀속년도 | DSD·정산표 기수 표기 변경 |
| 전기 감사후 수치 확정 여부(Y/N) | N이면 이월 중단(전기 수치가 확정 전이면 이월 무의미) |
| 산출물 파일명 규칙 | 예: `wp_일반조서_2025.xlsx` — 기본값 제시, 수정 가능 |

**사후 결정값**(초기세팅 시점에는 공란으로 생성, 프로그램이 값을 넣지 않음):
감사보고서일, 감사의견, 강조사항/기타사항, 중요성 확정값, 계속기업 결론 등.
→ 조서·DSD의 해당 칸은 비워 두고 `[입력 필요]` 표식만 남긴다. 보고서 단계에서
프로그램이 미입력 항목 목록을 보여주고 입력받는다 (§4).

### 2.3 실행 내용 — 발주자 작업순서 7단계의 자동화 매핑

| 수작업 (현행) | 자동화 동작 |
|---|---|
| 1. 전기 DSD·조서·정산표를 당기 폴더에 복사 | 전기 파일 3종+DSD를 당기 파일명으로 복사 생성 (원본 그대로 보존) |
| 2. 당기 DSD 세팅: 당기→전기 복사, 전기 지우기, 귀속년도·기수 변경 | DSD가 **엑셀 형식이면** 자동 수행. 전용 편집기 포맷(.dsd 등)이면 §2.5 참조 |
| 3. 전기 정산표 CF·FN 시트: 당기값→전기값 위치로 값복사 | 자동: CF/FN 시트에서 당기 열의 "값"을 전기 열에 붙여넣기(수식 아닌 값) |
| 4. 정산표 전기값 우측 열 추가 후, 전기 정산표의 당기수치를 값복사 | 자동: AR 시트에 열 삽입 + 값복사 (열 좌표는 템플릿 프로파일로 관리) |
| 5. BS·PL 당기→전기 값복사 | 자동 |
| 6. 정산표 당기 숫자 업데이트 | **당기 Raw data(시산표/총계정원장)에서 자동 주입** + 차대검증·합계검증 후 결과 리포트. Raw 매핑 불가 계정은 목록으로 표시(추측 매핑 금지) |
| 7. DSD 복사용 시트 정합 확인 | 자동 검증: 정산표 BS/PL/CF ↔ DSD 복사용 시트 셀 대사 → 불일치 목록 리포트 |

**당기 조서 생성**: 일반조서는 Index·각 시트의 작성일/검토일/전기 수치를 비우고
결산일·기수를 당기로 변경(작성자 이름은 유지 여부 선택). 계정별조서(4000)는
당기 표지로 세팅하고 담당자 열은 비움. → kgaapaudit의 "전기 이월 날짜 부정합" 문제가
원천적으로 방지된다.

### 2.4 안전장치

1. **Dry-run(미리보기)**: 실행 전 "생성할 파일 / 수행할 변경" 목록을 보여주고 확인받는다.
2. **원본 불변**: 전기 파일은 읽기만. 산출물은 전부 새 파일. 동명 파일 존재 시 덮어쓰지 않고
   `_v2` 붙이고 경고.
3. **실행 로그**: `_audit_tool/runlog.jsonl`에 실행시각·입력값·생성 파일·검증 결과·원본 해시 기록.
4. **검증 실패 시 중단**: 차대 불일치, 전기말↔당기초 불일치, DSD 대사 불일치는
   결과 리포트에 표시하고 해당 단계에서 멈춘다 (임의 보정 금지).

### 2.5 DSD 파일 — 확인 필요

"DSD"가 ① 엑셀 형태의 DSD 작성용 파일인지, ② 전용 편집기 파일(금감원 DART/DSD 편집기 등
비엑셀 포맷)인지에 따라 자동화 범위가 다르다.
- ①이면 기수·연도 변경과 당기→전기 이동까지 전부 자동화.
- ②이면: 정산표의 "DSD 복사용 시트"까지 완벽히 준비 + 편집기에서 할 나머지 작업을
  체크리스트로 출력. (포맷 파악 후 자동화 가능성 재검토)
→ **발주자 확인 필요: DSD 파일의 확장자와 사용 편집기.**

## 3. 모듈 ② 다업체 진행현황 관리

### 3.1 관리 단계 (8단계 — 발주자 정의)

```
1 조회서 안내 → 2 감사자료 요청 → 3 자료 다운 완료 → 4 보고서 초안완료
→ 5 심리 완료 → 6 보고서 송부 → 7 공시 → 8 인쇄 및 청구
```

### 3.2 동작

- **업체 목록**: `C:\...\C 회계감사\` 하위 폴더 스캔 (예: `C-35 서우리테일★`).
  폴더명에서 관리번호(C-35)·회사명 파싱. ★ 등 표식의 의미는 확인 후 반영.
- **상태 저장**: `C 회계감사\_audit_tool\진행현황.json` — 업체×연도별 현재 단계,
  단계별 완료일, 메모. 변경 이력은 append 기록.
- **자동 추정 + 수동 확정**: 폴더 내 파일과 도구 실행 기록으로 단계를 *추정*하고
  (예: 조회서 발송파일 존재→1, rawdata 존재→3, DSD PDF 존재→4 이상,
  심리(8600C) 작성→5), 사용자가 클릭으로 확정한다. 추정≠확정을 UI에 구분 표시.
- **대시보드**: 업체×단계 매트릭스 HTML 생성(색상: 완료/진행/지연). 기존 kgaapaudit
  스킬의 조서 단위 상세 분석과 연동 — 대시보드에서 업체 클릭 시 kgaapaudit 리포트 열기.
- 4~8단계(초안→심리→송부→공시→청구)는 문서로 자동 판정이 어려운 항목이 많으므로
  **수동 체크가 기본**, 파일 신호는 보조.

## 4. 의사결정 입력 체계 (전 모듈 공통)

프로그램이 결정하지 않는 값의 단일 관리 방식:

- 업체 폴더에 `_audit_tool/결정값.json` (GUI 폼으로 편집) — 사전/사후 구분, 각 항목에
  ①무엇을 결정하는 것인지 ②어디에 반영되는지 ③미입력 시 무엇이 막히는지 표시.
- **게이트**: 사후 결정값(감사의견 등)이 비어 있으면 보고서 완성 단계(DSD 확정·PDF 생성)를
  진행하지 않고 미입력 목록을 보여준다. 기본값 자동 채움 없음.

| 구분 | 항목 예 | 미입력 시 |
|---|---|---|
| 사전 | 기수·귀속년도·결산일·파일명 규칙 | 초기세팅 실행 불가 |
| 기중 | 중요성 확정값, 유의적 위험 지정 | 관련 조서 `[입력 필요]` 유지 |
| 사후 | 감사보고서일, **감사의견**, 강조사항, 계속기업 결론 | 보고서·PDF 생성 차단 |

## 5. 전체 작업흐름 매핑 (발주자 순서 → 프로그램 지원 범위)

| 발주자 작업 | 프로그램 지원 (1차 릴리스) |
|---|---|
| 초기세팅 1~7 | **모듈 ①로 완전 자동화** (DSD는 §2.5 확인 후 범위 확정) |
| 은행연합회 월보·조회서 정리, 특관자, 총괄원장 다운 | 진행현황 1~3단계 체크 + 수령파일 자동 분류(kgaapaudit 엔진 재사용). 다운로드 자체는 수동 |
| 더존(위하고) 자료 다운로드 | 수동 (다운 후 폴더에 넣으면 자동 분류·검증). 더존 API 연동은 장기 검토 |
| 감사절차 수행·조서 작성 | 1차: 진행현황 추적 + 조서 상태 점검(kgaapaudit). 조서 내용 자동화는 웹 시스템(장기) 영역 |
| 감사보고서 주석 작성 | 1차: 전기 FN 시트 이월 세팅까지. 주석 자동 작성은 장기 |
| 정산표·주석 → DSD 복사 | 자동 값복사 + 대사 검증 |
| 매핑 오류·누락 주석 검토 | **자동 검증 리포트**: BS/PL/CF/FN ↔ DSD 시트 대사, 합계 검증, 누락 항목 목록 |
| DSD 완성·PDF 생성 | 사후 결정값 게이트 통과 시 지원 (PDF 생성은 DSD 포맷 확인 후) |

## 6. 구현 순서 (데스크톱 도구)

| 단계 | 내용 | 산출물 |
|---|---|---|
| D1 | 파일 자동 식별 + 폴더 스캔 엔진 (kgaapaudit 분류 로직 재사용) | 식별 결과 화면 |
| D2 | 초기세팅 자동화: 복사 생성 + 정산표 이월(3·4·5단계) + 조서 당기화 | 당기 파일 생성 |
| D3 | 당기 Raw 주입(6단계) + 검증(차대·대사·7단계) 리포트 | 검증 리포트 |
| D4 | 결정값 입력 폼 + 게이트 | 결정값.json |
| D5 | 진행현황 관리 탭 + 대시보드 HTML | 진행현황.json/대시보드 |
| D6 | exe 패키징, 실사용 테스트(서우리테일 폴더) | 배포본 |

각 단계는 발주자 실파일 1개 업체로 검증 후 다음 단계 진행.

## 7. 구현 전 확인 필요 (발주자)

1. **DSD 파일의 확장자·편집기** (§2.5) — 자동화 범위를 좌우하는 가장 큰 변수.
2. **정산표 AR 시트의 열 구조 고정 여부** — 업체마다 열 배치가 다르면 템플릿 프로파일 방식으로
   흡수(첫 실행 시 열 매핑 확인 화면).
3. **당기 Raw data의 표준 구성** — 더존(위하고) 내보내기 형식 샘플 1세트
   (재무상태표·손익·분개장·부속명세서 등) 제공 가능 여부.
4. **폴더·파일 명명 규칙** — `C-35 서우리테일★`의 ★ 의미, 연도 폴더 규칙
   ("2025년 기말감사" 고정 여부).
5. **실행 환경** — 발주자 PC에 Python 설치 가능 여부 (불가하면 exe 배포 전제).
