# 보안 모델 (Security Model)

- 버전: 1.0 · 기준일: 2026-07-30

## 1. 인증·인가 (RBAC)

- 인증: JWT + 서버측 세션 무효화 목록. 비밀번호는 argon2/bcrypt 해시.
- 인가: **역할(role) × 업무 멤버십(engagement_members) 이중 스코프**.
  해당 감사업무에 배정되지 않은 사용자는 역할과 무관하게 그 업무 데이터에 접근 불가.
- 역할: Admin / Engagement Partner / Manager / Senior / Staff / Read-only Reviewer / Client User.
- Client User는 자료 제출·질의 답변 전용 라우트만 접근(라우터 물리 분리). 감사위험·조서·차이·의견
  관련 API는 코드 레벨에서 감사팀 역할만 허용.
- **자기승인 금지**: preparer == reviewer 또는 proposer == approver인 상태 전이는 도메인 계층에서 거부.
- 승인 게이트는 프론트엔드가 아닌 **도메인(서비스) 계층에서 강제** — API 직접 호출로 우회 불가.

## 2. 파일 저장 (확정: Google Drive)

발주자 결정에 따라 원천자료 저장과 산출물 백업 모두 Google Drive를 사용한다.

- 구현: `StorageInterface` 추상화 — dev: `LocalStorage`(로컬 파일시스템), 운영: `GoogleDriveStorage`
  (서비스 계정 + 감사업무별 전용 폴더, 최소 권한 공유).
- **원본 불변성 통제** (Drive 파일은 기술적으로 수정 가능하므로 다음으로 보강):
  1. 업로드 즉시 SHA-256 해시를 DB에 기록 (documents.sha256)
  2. 애플리케이션에 원본 수정·삭제 API 자체가 없음
  3. 주기적 해시 재검증 잡 — 불일치 시 무결성 경보 + 해당 자료 사용 차단
  4. Drive 파일 버전 이력 보존 활성화
- 파싱·정규화 결과는 원본과 분리된 DB 테이블에 저장. 원본은 어떤 절차에서도 덮어쓰지 않는다.

## 3. 감사추적 로그 (Audit Trail)

- `audit_trail` 테이블: append-only. 애플리케이션 DB 계정에 UPDATE/DELETE 권한 미부여.
- 각 행에 prev_hash → row_hash 해시 체인으로 변조 탐지.
- 기록 대상: 데이터 변경, 판단 변경, 상태 전이, 검토·승인, 로그인·권한 변경, 파일 업로드·다운로드.
- 기록 내용: 행위자, 시각, 대상 엔터티, 이전값→새값(마스킹 후), 사유.

## 4. AI 데이터 송신 정책 (확정 결정 + 권고)

**발주자 확정 결정: Anthropic API로 원문 그대로 송신한다.**

단, 다음 상충점과 법적 제약을 명시한다.

1. **원 요구사항 §1과의 상충**: 요구사항은 "개인정보와 고객정보는 외부로 전송하지 않는다"였으나,
   발주자 결정으로 AI 분석 품질을 위해 원문 송신을 허용한다. 이 결정은 발주자 책임 하의
   정책 변경으로 기록한다.
2. **고유식별정보 예외 (강력 권고, 기본 ON)**: 주민등록번호 등 고유식별정보는 개인정보보호법상
   처리 제한 대상이므로, 송신 전 자동 마스킹을 기본 활성화한다. 관리자 설정으로 제어 가능하되
   해제 시 audit_trail에 기록된다.
3. **로그 마스킹은 유지**: 시스템 로그·audit_trail·ai_tasks.raw_response 저장본에는 원 요구사항대로
   개인정보 마스킹을 적용한다 (송신 정책과 저장 정책은 별개).
4. **계약상 고지**: 피감사회사 정보의 제3자(AI 사업자) 처리위탁에 대해 감사계약서 또는
   별도 동의로 고지할 것을 권고한다.
5. 송신 이력: 모든 AI 호출은 ai_tasks에 입력 참조·모델·프롬프트 버전·시각과 함께 기록된다.

## 5. 시크릿 관리

- API key·비밀번호·DB 접속정보는 환경변수 또는 시크릿 매니저로만 주입. 코드·저장소에 하드코딩 금지.
- `.env`는 gitignore, `.env.example`에는 키 이름만.
- pre-commit + `.claude/hooks`로 시크릿 패턴(API key, private key, 비밀번호) 커밋 차단.

## 6. 개인정보 처리

- 마스킹 패턴: 주민등록번호, 외국인등록번호, 계좌번호, 카드번호, 전화번호, 이메일(선택),
  급여 데이터의 개인 식별 조합.
- 마스킹 적용 지점: ① 로그 기록 전 ② audit_trail 저장 전 ③ AI 원문 응답 저장 전
  ④ (권고 기본 ON) AI 송신 전 고유식별정보.
- 보존 연한: 감사조서 보존 의무(외감법 8년)에 맞춘 보존·파기 정책 — 세부는 발주자 확정 대기(C13).

## 7. 위협 대응 요약

| 위협 | 통제 |
|---|---|
| 승인 우회 | 도메인 계층 게이트, 자기승인 거부, approvals 단일 원장 |
| 감사로그 변조 | append-only + 해시 체인 + DB 권한 제거 |
| 원본 훼손 | 수정 API 부재 + 해시 재검증 + Drive 버전 이력 |
| 업무 간 데이터 접근 | role × engagement 이중 스코프 |
| 시크릿 유출 | 환경변수 주입 + 커밋 차단 훅 |
| 외부회신 위·변조 | 시스템은 진위 판단을 하지 않음을 UI 명시, 수령 경로·담당자 기록 |
