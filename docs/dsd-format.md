# DSD 파일 형식 분석 (확정)

- 기준일: 2026-08-03 · 근거: 발주자 제공 샘플(FY2025 감사보고서 .dsd) 분석 및 이월 PoC 성공

## 1. 파일 구조

`.dsd` = **ZIP 컨테이너** (표준 zip, 압축 해제·재압축 가능):

| 내부 파일 | 내용 |
|---|---|
| `contents.xml` | 문서 본문. 금감원 DART 편집기 스키마(`dart4.xsd`), UTF-8 |
| `meta.xml` | 문서 메타 (편집기 버전, 회사 regcik/regname, 문서 ID, 요약 EXTRACT 항목) |

## 2. contents.xml 구조

```
DOCUMENT
├─ DOCUMENT-HEADER
│  ├─ DOCUMENT-NAME (ACODE=00760 감사보고서)
│  ├─ COMPANY-NAME (AREGCIK, AACCOUNTTYPE)
│  └─ SUMMARY/EXTRACTION*  ← 요약값: AUDIT_CIK, GMSH_DATE(주총일), TOT_ASSETS,
│                             TOT_DEBTS, TOT_SALES, TOT_EMPL, IFRS_YN, PREV_IACS 등
└─ BODY
   ├─ COVER, TOC
   ├─ SECTION-1* : 독립된 감사인의 감사보고서(본문) / (첨부)재무제표
   │   재무상태표·손익계산서·자본변동표·현금흐름표 / 주석 / 외부감사 실시내용
   └─ TABLE > (THEAD|TBODY) > TR > (TH|TD|TE) 표 구조
```

## 3. 자동화 핵심 포인트

### 3.1 재무제표 수치 셀 — `TE` 요소

- `ACODE`: 표준계정코드 (예: `11200000040000` = 유동자산) — 행 식별자
- `ADELIM`: 열 위치. **0=계정명, 1·2=당기 열, 3·4=전기 열**
- 값은 요소 text에 쉼표 서식 문자열(예: `9,586,490,807`)

→ **이월(Rollforward)**: 같은 ACODE 행에서 ADELIM 1→3, 2→4로 text 이동 후 당기열 비움.
→ **당기 수치 주입**: 정산표/시산표에서 ACODE 매핑으로 당기열 기입 (매핑표는 account_mappings 재사용).

### 3.2 기수·연도 라벨 — `TD`/`TH` text

패턴: `제 12(당) 기`, `제 11(전) 기`, `제 12 기 2025년 12월 31일 현재`,
`제 12기 2025년 1월 1일부터 2025년 12월 31일까지`
→ 정규식 치환으로 기수 +1, 연도 +1. **주의**: 한글 접미사("년") 앞에서 `\b`가 동작하지
않으므로 `(?<!\d)202[0-9](?!\d)` 형태 사용 (PoC에서 실증된 버그).

### 3.3 사후 결정값 (프로그램이 넣지 않는 값)

- 감사보고서일 (본문 "감사보고서일(YYYY년 M월 D일)" 문구) → `[입력 필요]`로 공란화
- 감사의견 문단, 강조사항, 핵심 문구 → 전기 텍스트가 남으므로 **검토 필요 목록**으로 표시
- SUMMARY의 GMSH_DATE(주총일), SUPV_OPIN 등 → 사후 입력 게이트 항목

### 3.4 재압축

zip으로 재압축(contents.xml + meta.xml)하면 편집기에서 열리는 .dsd가 된다.
meta.xml의 FILE-INFO(size 등) 필드 갱신 필요 여부는 편집기 실호환 테스트로 확인한다
(PoC 산출물을 DART 편집기에서 열어보는 것이 최종 검증).

## 4. PoC 결과 (2026-08-03)

FY2025 완성본 → FY2026 이월 세팅 시험:

- TE 셀 값 이동(당기→전기) 186개, 당기열 비움 378개 — 유동자산 등 표본 검증 통과
- 기수·연도 라벨 치환 59건 (`제 13(당) 기`, `제 13 기 2026년 12월 31일 현재` 확인)
- 감사보고서일 공란화 1건
- 새 .dsd 재압축 및 재파싱 정상

**남은 확인**: 생성된 시험 .dsd가 발주자 PC의 DART 편집기에서 정상적으로 열리는지
(편집기의 자체 무결성 검사 여부). 열리면 자동화 범위 100% 확정.

## 5. 전산자료(더존/위하고) 표준 구성 — 발주자 샘플 기준

| 시트 | 내용 | 프로그램 활용 |
|---|---|---|
| RQ | 요청자료 목록·회신 관리 | 진행현황 2·3단계 신호 |
| ARAP | 채권채무 거래처 명세(사업자번호·이메일) | 조회서 발송 목록 생성 |
| BS / PL | 더존 재무상태표·손익 (당기/전기 열) | 정산표 당기 수치 주입 원천 |
| 당기수정사항 / 전기수정사항 | 수정분개(AJE) | SAD 시트 연계, 왜곡표시 평가 |
| 명세서 | 예금 등 계정 명세 | 계정별조서 근거 |
| 24특관자 / 25특관자 | 특수관계자 거래·잔액 | 3500 조서 근거 |
| 25 (연도 시트) | 분개장 전체 (18만 행+) | 이상분개 탐지, 대사 |
| G | 유형자산 대장 | G 조서 근거 |
| 월보 | 은행연합회 월보 조회 | 차입금 대사 |
| 조회서 | 금융기관 조회서 정리 | A10 조서, 조회 차이 분석 |

파일 1개에 감사 필요 원천자료가 대부분 집적되어 있어, **이 파일 하나를 당기 Raw 표준
입력으로 삼는다** (시트명 프로파일: RQ/ARAP/BS/PL/명세서/특관자/연도분개장/G/월보/조회서).
